Features

  • Learns on the chip. Forward, backward and SGD run on a Cortex-M4F, not just inference of a frozen model.
  • No heap, no std, no runtime. The network is a Rust type; a shape mismatch is a compile error.
  • Measured on the board. Cycle counts from the DWT counter over ST-Link, with the conditions next to every number.
  • One core, three kinds of signal. Sound, images and time-of-flight range, all aimed at the same 128 KB.
  • Limits written down. What doesn't work yet sits next to the results, not after them.

frugal_ml

Linear algebra and reverse-mode autodiff that train small neural networks on a microcontroller, with no heap and no runtime.

Most machine learning on microcontrollers is inference only: train on a GPU, freeze the weights, flash them. The device can never adapt to its own sensor, its own noise or its own drift. frugal_ml runs the backward pass and the weight update on the chip as well.

Without a heap there is nowhere to keep the usual autodiff tape, so the graph is a type instead: seq!(A, B, C) becomes Then<A, Then<B, C>>, and the compiler resolves every forward and backward call, and checks every shape, before the binary exists. Nothing is dispatched at runtime.

A network is a typerust
let mut net = seq!(
    Linear::<4, 16>::from_seed(42),
    Tanh::<16> {},
    Linear::<16, 3>::from_seed(137),
    Softmax::<3> {}
);

// one training step, entirely on the device
let (out, ctx)   = net.forward(input);
let (loss, grad) = cross_entropy(out, target);
let (_, grads)   = net.backward(grad, &ctx);
sgd(&mut net, &grads, 0.05);

Known limits

  • Static architectures onlyNothing in the graph can depend on a runtime value: no early exit, no per-sample routing.
  • Sequential chains onlyThen can't express a value used twice, so no skip connections (ResNet) yet.
  • SGD only, on purposeAdam's two moment buffers would double the optimizer's RAM. Momentum, one buffer, comes first.
  • Convolution is inference-onlyThe streaming convolution works, but it isn't a trainable layer yet.

Cancelling noise by learning it, one sample at a time

An adaptive filter trained online on the microcontroller: the simplest case of on-device learning, and a real signal-processing tool.

A microphone hears a signal mixed with engine-like noise. A second sensor hears only the noise, through a path nobody measured. A single neuron with 16 weights learns, sample by sample, to predict the noise from that reference; subtracting its prediction leaves the signal. In frugal_ml this needs no special code: Linear<16, 1> + mse + Sgd is exactly the Widrow–Hoff LMS filter.

The chip was measured at 16 taps only (575 cycles). Other lengths are projected on a straight line through that point: with a single output, forward, backward and update are each one pass over the taps, so the cost is linear by construction. The chip's run was 375 ms long, so its "converged" window is 335–375 ms. Push to 128 taps at 96 kHz and the chip can no longer keep up.

When the frame doesn't fit: convolution in 128 KB

The same 3×3 convolution held in memory four ways, against a chip whose whole stack is 126.4 KB.

A 1280×720 frame, two filters and their outputs take 11 MB: 91 times what the chip can hold. directConv drives frugal_ml from Python and compares the ways out. Keep the full frame on the stack: fast, but the largest 16:9 frame that fits is 128×72. Put it on the heap: the chip has no allocator. Shrink the frame: you lose pixels. Or stream it.

Streaming (ConvStreaming) keeps only the three input rows each filter needs. Memory then depends on the frame's width, not its height: 46 kB for 1280-wide video. The price is speed, about 1.2 frames per second at 720p on the chip.

On a laptop (Apple M4 Pro), frugal_ml's full-frame path takes 0.55 ms per 720p frame where numpy takes 11.4 ms, and the outputs are identical. The arithmetic isn't faster: 81 % of numpy's time is one copy. np.tensordot needs a flat matrix for BLAS, so it materialises every 3×3 window, 33 MB per frame; frugal_ml's tensordot_3 reads the same windows through strides and never copies them.

The gap closes as filters are added: with 16 filters numpy's single copy is shared by all of them and the two are roughly level (0.9×).

Sentinel: a time-of-flight radar that tracks what moves

No camera. An 8×8 depth sensor on a pan-tilt arm scans, separates moving objects from the background, locks onto one and tracks it, with the whole estimation loop on the microcontroller.

The sensor sees in 64 cones of about 5.6° each, which fixes a trade-off no software removes: at a few metres a moving object is a coarse blob, as it would be for a real radar, and fine contours such as the fingers of a hand only resolve at 20 to 30 cm. So the plan has two modes: a fast wide scan for detection and tracking, and a slow fine raster on a close target.

Everything is written from the datasheet up: servo PWM, the I²C sensor driver, clustering, the Kalman filter on frugal_ml tensors, the serial protocol, and a software 3D renderer on the Mac side.

Classifhear: recognising city sounds, headed for the edge

Sirens, drills, dog barks, engines: ten classes of urban sound, to be classified on a microcontroller in the end. For now, the groundwork: what a frame of audio is.

Three weeks in, the work is feature extraction written by hand before reaching for the library versions: amplitude envelope, RMS energy, zero-crossing rate. The first real lesson came from a test impulse: computing each value from the start of its frame shifts every curve half a frame early. Frame length and hop turned out to be the same trade-off as a convolution's kernel and stride: overlap keeps context, and costs compute.
